## The Brutal Truth

Phase 5 E2E test initially failed because `composite_service.get_or_create_composite` calls real `urllib.request.urlopen` to fetch template base image when R2 reports cache miss. Test mocked R2 to return `exists=False`, forcing a re-fetch that hit the un-mocked urllib. Caught at the last moment—2 hours before ship.

**Frustration**: This was a seam in the test fixture. Mock scope creep. Should've caught during Phase 4 when composite service was finalized, not Phase 5. Cost 30m debug → fix → re-run.

## Technical Details

**Key architectural decisions shipped:**

1. **Per-color base images as JSON map on Template** (not new table)
   - Trade-off: KISS migration (single column), but schema-less → runtime validation only
   - Variation convention: `variation_options_json.color_bases = {"White": "white-base.png", "Black": "black-base.png"}`

2. **Idempotency via Listing row** (not Etsy idempotency-key header)
   - Etsy v3 has no native idempotency-key
   - Solution: `Listing(template_id, design_id)` composite index + early return on exists
   - Edge case handled: partial failure (title OK, image upload fail) — tested & works

3. **Apparel taxonomy hardcoded** (category 1209, color=200, size=506)
   - Apparel-only for v0.4.0; other categories (mug 23286, poster 23281) require taxonomy mapping in v0.5.0+
   - Cache misses rare (~2-3 per workflow); in-memory dict sufficient

4. **Sequential image upload with 200ms gap**
   - Stays below Etsy 5 req/s soft limit
   - Retry-once-on-429 via existing `etsy_api_client._request` loop
   - Primary color → rank 1, rest by template order

5. **Draft only, never publish**
   - Seller finalizes from Etsy UI
   - Reduces liability; aligns with reference mode philosophy

## What We Tried

1. **Parallel image upload** → Shelved; sequential + 200ms sleep simpler + safer rate-limit margin
2. **Etsy idempotency-key header** → Not available in v3 API; switched to DB check
3. **Dynamic taxonomy mapping** → Over-scoped; hardcoded apparel for v0.4.0
4. **Mock R2 to always report `exists=True`** → Initial approach; broke upstream composite cache validation. Final fix: mock `exists=True` only during from-template flow, let full test suite exercise cache miss path separately

## Root Cause Analysis

E2E test friction stemmed from **crossed mock boundaries**: composite_service expects R2 to handle "exists" check reliably, but test mocked R2 without considering composite's internal call to urllib when cache miss occurs. Test isolation broke; fixture was incomplete.

**Why it happened**: Phase 4 & 5 were sequential (both modify listing_creator_service.py). Temptation to mock aggressively in Phase 5 to "skip expensive operations." Didn't think through mock layering — R2 mock needed context about what composite service would do downstream.

## Lessons Learned

1. **Mock scope must match call scope.** If a service method makes external calls (urllib.urlopen), mock must cover the full call chain, not just the entry point. Document mock assumptions in the test.

2. **Seams appear when mocks sit between layers.** Composite service ← R2 ← test fixture; when R2 mock is incomplete, composite can't handle the contract correctly. Better: mock at entry point (e.g., R2StorageClient.get_bytes) and let intermediate calls work naturally, or document that intermediate calls are stubbed.

3. **Phase sequencing matters for test fixtures.** Phases 1-2 (composites) should have settled on mocking strategy before Phase 5 (E2E) tries to reuse them. Found this gap too late; lucky catch.

4. **Apparel taxonomy hardcoding is acceptable debt.** Adding dynamic taxonomy_id lookup would add 2h to Phase 3, but only saves ~30 min per new POD category. v0.5.0 can tackle it when we ship mugs. Correct call to YAGNI here.

5. **Idempotency via Listing row is right call.** Etsy's missing idempotency-key is their design gap; we compensated well. Partial-fail scenario (title OK, image fails) tested + works. Seller can re-click from extension safely.
