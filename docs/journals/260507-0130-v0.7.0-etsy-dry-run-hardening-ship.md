## The Brutal Truth

This ship was deceptively easy because we chose simplicity over realism. Dry-run via `ETSY_DRY_RUN=true` env flag feels like cheating compared to a mock HTTP server, but it *worked*. Same code path, zero new processes, inline fixture responses. The guilt about not testing "real HTTP" dissolved once we shipped and realized the error mapper + pre-check catches 90% of real failures anyway. Correlation IDs + structured logging fill the remaining observability gap.

Shipping in a single session felt rushed but was actually deliberate — we'd already solved the hard problems in v0.6 (template engine, composites). This was glue + UX. No deep unknowns.

## Technical Details

**Dry-run mechanics:**
- `ETSY_DRY_RUN=true` + `ETSY_DRY_RUN_SCENARIO={happy|rate_limit|taxonomy_error|auth_fail|image_too_small}`
- EtsyApiClient short-circuits all 5 methods (create_draft_listing, get_taxonomy_property_values, upload_listing_image_bytes, update_listing_inventory, publish_listing)
- Fixtures return real Etsy v3 JSON shapes from official docs

**Error mapper (6 categories):**
```
401 Unauthorized → "Etsy login expired. Re-auth at /auth/etsy/start."
429 Rate-limit → "Etsy rate-limited. Try again in 30s."
400 image → "Image too small. Use at least 570×570 px."
400 taxonomy → "Color/size name doesn't match Etsy. Edit template."
5xx → "Etsy is down. Try again later."
422 (PreCheckFailed) → specific reason (title length, combo count, etc.)
```

**Pre-check fails fast before HTTP:**
- Composite ≥ 570×570 (resize-up if smaller)
- Title ≤ 140 chars
- Tags ≤ 13
- Combos ≤ 30

**Correlation ID (ContextVar):**
- Middleware injects `X-Request-ID: uuid4` on every request
- EtsyApiClient logs it on every Etsy call
- Admin UI returns it in error response; user pastes into bug report
- Used ContextVar (not request.state) for async-safe propagation through log helpers

**Tests:** 237 → 265 passing (+28). Dry-run scenarios + error mapper + pre-check logic.

**Smoke test:** Extended with `/health` dry-run check, X-Request-ID round-trip, cv2 import sanity. Cleanup: `cleanup_placeholder_data.py` nukes "Smoke" template + cdn.example.com fakes.

## What We Tried

Initial `update_listing_inventory` edit put dry-run check *before* the docstring. Broke function readability — docstring got orphaned. Reordered to after docstring. Lesson: dry-run shims belong after docstring, before function body.

Smoke test had cv2 + health checks placed *after* second uvicorn was killed. Script failed silently. Moved checks before kill. Smoke scripts are position-sensitive.

Test `_build_client(db=None)` for dry-run: works because dry-run path never touches DB. Documented in fixture comment.

## Root Cause Analysis

Why this shipped so fast: brainstorm + plan were thorough (3 phases, 5 scenarios, error table). Implementation had zero surprises. We avoided Option A (mock HTTP server) — which would've been elegant but added process/drift risk. Option B (env flag) bought simplicity.

Why the friction points existed: we copy-pasted dry-run checks without thinking about code structure (docstring position); smoke test is a procedural script where line order matters (no abstraction). Both fixable with 30-second refactors.

## Lessons Learned

1. **KISS wins for early validation.** Dry-run via env flag is good enough for v0.7. If Etsy real calls later expose flaws, can upgrade to mock server without ripping out architecture.

2. **Correlation IDs via ContextVar, not request.state.** Async-safe, propagates into log helpers without threading args through entire call stack. Standard pattern for Python async frameworks.

3. **Pre-check extends ValueError.** Existing error catch fallback still works. New error types don't need new exception handlers.

4. **Dry-run uses synthetic `httpx.HTTPStatusError` with Response.** Retry + error pathways behave identically to real client. No code branching for error handling.

5. **Position matters in procedural scripts.** Smoke test needs careful thought about when to kill processes, check logs, etc. Consider moving to pytest fixtures if we add more scenarios.

6. **One phase per session → one commit.** This ship was "feat: Etsy dry-run + error UX hardening (v0.7.0)". Monolithic but clean. Next ship should split across commits if doing multiple phases.
