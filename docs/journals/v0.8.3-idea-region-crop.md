# v0.8.3 — Idea → Listing region-crop

**Shipped:** 2026-05-12
**Plan:** [`260512-1104-idea-to-listing-region-crop`](../../plans/260512-1104-idea-to-listing-region-crop/plan.md)
**Brainstorm:** [`brainstorm-260512-1104-idea-to-listing-region-crop.md`](../../plans/reports/brainstorm-260512-1104-idea-to-listing-region-crop.md)

## What shipped

Native admin crop-modal in the idea wizard. One click on a mined idea now opens a drag-rectangle modal over the reference image; release fires `POST /admin/ideas/{id}/extract-design`, which PIL-crops the selected region, runs remove.bg, uploads a PNG to R2, and creates a `Design(source_type='derivative')` linked back to the idea via the new `idea.design_id` FK. Step 2 of the wizard pre-selects that design on the next view.

Re-extraction is idempotent: the same Design row is updated in place (old R2 object deleted, file_url overwritten). Backend ships with 14 unit tests; full suite at 421 passing.

## Why

v0.8.0 promised the chain `keyword → idea → wizard → Etsy draft`, but the user kept hitting the same dead-end: the wizard's Step 2 requires a Design row, and there was no way to produce one *from the idea's reference image*. The only working path was "upload a new PNG", which assumes the user already drew the artwork. For a seller workflow that starts by spotting a winning design on a competitor's listing, this gap broke the whole story.

`extension/side-panel/crop-modal.js` had solved the same drag-rectangle UX in a different context. The cheap move was to port it server-side rather than refactor it into a shared lib for two callers. Tech debt is tracked; we revisit when a 3rd usage appears.

## Design decisions

- **New `source_type='derivative'`** instead of bypassing the `reference_only` filter. Old inspiration cutouts still blocked. New crops are explicitly the seller's compliance call, recorded in the type itself.
- **Auto-link via `idea.design_id` FK (nullable)** — one active derivative per idea. Re-extract overwrites. Keeps the Step 2 pre-select trivial (`{% if idea.design_id == d.id %}checked{% endif %}`).
- **Endpoint per-idea `/admin/ideas/{id}/extract-design`** — did *not* reuse `/references/{id}/cutout`. Reasoning: that path creates a Reference row, and we'd be forging one just to satisfy the type system. The new endpoint owns its own validation, download, crop, removebg, R2, upsert flow.
- **Port crop-modal.js to admin-crop-modal.js** instead of extracting a shared module. Extension runs in Chrome DOM with content scripts; admin runs in server-rendered Jinja. Refactor when 3rd context shows up.
- **No grid snap, no multi-region MVP.** Deferred.

## Risks (acknowledged)

- **Etsy DMCA / ToS:** user-acknowledged business decision. The IP banner in Step 1 of the wizard repeats the warning. The `derivative` source_type makes this explicit at the data layer.
- **Etsy duplicate-image detection:** Even with a different mockup template, Etsy may flag near-identical crops. Out-of-scope for ship. The Imagen "make it different" variation pass (Approach C in the brainstorm) is queued for v0.9.
- **Cutout quality on noisy edges:** mockup artifacts can survive remove.bg. User can re-extract; the modal renders the source image at full size so the rectangle is precise.

## Tech debt

- `admin-crop-modal.js` ↔ `extension/side-panel/crop-modal.js` duplication. Same drag-math, different DOM context. Refactor trigger: 3rd caller.
- `update_design_file()` in `design_service` accepts `r2_key` for symmetry but only persists `file_url`. The key is the URL suffix and is reconstructed by the caller for cleanup. Leaves a small redundancy but keeps the Design schema unchanged.
